# 充电桩边缘服务器设计

## 链路与安全

客户端不直接连接充电桩。所有业务均沿以下链路执行：

```text
Qt 桌面/手机客户端 --TLS 1.2+--> 中心服务器 --TLS 1.2+--> 充电桩边缘服务器
```

中心服务器和充电桩使用与现有客户端相同的“4 字节大端长度 + JSON”帧格式和证书固定校验。充电桩首次连接发送 `device.register`，并用 `device/token` 共享凭据登记自己管理的电桩编号。真实部署应为每个站点分配不同凭据，本课程版本使用一个配置项便于演示。

## 本地 SQLite

充电桩端默认数据库为 `data/charger-edge.db`，包含：

- `chargers`：编号、类型、额定功率、当前状态、累计次数和时长；
- `charge_orders`：中心订单号、用户、模式、目标、起止时间、电量、时长、金额和同步状态；
- `telemetry`：电压、电流、功率、SOC 和累计电量采样。

本地订单主要状态：

- `CHARGING`：本地持续计量，即使中心连接中断也不停止；
- `SYNC_PENDING`：已经在充电桩停止，等待中心服务器结算确认；
- `COMPLETED`：中心结算成功，双方状态一致；
- `CANCELLED`：中心启动失败后撤销。

## 开始充电

1. 客户端经 TLS 登录并发送 `charge.start`。
2. 中心服务器校验用户、余额、模式、目标和电桩状态，先建立 `STARTING` 订单。
3. 中心服务器确认该电桩存在已登记的 TLS 会话，然后发送 `device.order.start`。
4. 充电桩把订单写入本地 SQLite 后返回确认。
5. 中心服务器把订单改为 `CHARGING`，最后才向客户端返回成功。

任何一方缺少连接或充电桩十秒内未确认，客户端都会收到失败结果，订单不会进入充电状态。

## 计费模式

- `AMOUNT`：目标单位为元；余额至少等于目标金额。
- `ENERGY`：目标单位为 kWh；预计费用为目标电量乘电站单价。
- `TIME`：目标单位为分钟；最大预计费用为 `分钟 / 60 × 额定功率(kW) × 电站单价`。

充电桩按本地计量数据判断目标。边界采样会裁剪到目标，避免因两秒采样步长造成余额校验后仍发生超额费用。

## 停止、断线与重连

客户端停止订单时，中心服务器必须能联系对应充电桩。连接断开时返回“充电桩与服务器连接断开，暂时无法停止订单”，充电桩仍继续本地计量。

充电桩重连后自动执行 `device.register` 和 `device.sync`：

1. 上报本地电桩状态，中心以本地状态为准；
2. `CHARGING` 订单同步最新电量和时长；
3. `SYNC_PENDING` 订单由中心扣款并生成钱包流水；
4. 中心返回结算成功后，充电桩才把本地订单改为 `COMPLETED`。

中心重启不会主动结束充电订单，客户端重新登录后会恢复当前活动订单号，可以在充电桩重连后继续停止。

## 验证

完成 Release 编译后执行：

```powershell
python tests\test_edge_integration.py
```

该脚本只使用系统临时目录中的数据库，覆盖三方启动、按时间自动停止、设备离线拒绝启动、断线本地计量和重连结算。
